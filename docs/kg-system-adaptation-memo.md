# LectureCraft 向け KG システム改良メモ

このメモは、助教の方から受け取った prerequisite knowledge graph 抽出コードを、**LectureCraft 上で使える形に最適化するために加えた改良**を整理したものです。  
教授向けには、「元コードをそのまま使ったのではなく、LectureCraft の用途に合わせて入力・保存・比較・説明制御の方向へ拡張した」と説明できます。

## 1. 出発点

元コードは、講義資料画像から **prerequisite triplet** を抽出し、

- `A Is-a-Prerequisite-of B`

のような関係を取り出して、前提知識グラフとして可視化する研究用プロトタイプでした。  
つまり主目的は、**教材に含まれる前提関係の抽出と可視化**です。

一方、LectureCraft では KG を単なる可視化対象ではなく、

- どの概念を重点的に説明するか
- どの順番で説明するか
- どのスライドを根拠にするか

を考えるための **生成制御用の中間表現**として使いたいので、そのままでは不十分でした。

## 2. LectureCraft 向けに加えた主な改良

### 2-1. 独立コードから Web アプリ API へ統合した

元コードは単独スクリプトとして動かす想定でしたが、LectureCraft では frontend から直接呼べる必要があるため、

- `POST /api/kg-preview`
- `POST /api/kg-preview/compare`
- `GET /api/kg-preview/variants`
- `GET /api/kg-preview/results`
- `GET /api/kg-preview/results/{result_id}`

という API 群に組み直しました。

これにより、

- PDF をアップロードしてそのまま KG 抽出できる
- 比較用の複数版を同じ UI から実行できる
- 過去の結果を再読込できる

ようにしています。

### 2-2. 入力を LectureCraft の PDF ワークフローに合わせた

元コードはスライド画像群を前提にしていましたが、LectureCraft では通常の作業起点が **PDF** なので、

- `pdf_base64 + filename`

を受け取って backend 側で画像化し、既存の PDF キャッシュと連携する形に変えました。

これにより、ユーザは KG のためだけに別の前処理を意識せず、通常の LectureCraft の資料読み込みフローのまま使えます。

### 2-3. 「1つの抽出器」ではなく「比較可能な variant 群」にした

研究用途では 1 つの出力だけを見るより、**複数の改良版を同条件で比較できること**が重要です。  
そのため backend 側に variant registry を作り、同一 PDF・同一 model に対して複数版を並列比較できるようにしました。

現在の主な variant は次の通りです。

- `原型 (raw)`
  - 助教コード由来の prerequisite 抽出をそのまま確認する baseline
- `根拠付き試作 (evidence_proto)`
  - 元の edge を維持したまま、根拠情報を追加する版
- `JSON整形版 (normalized_json)`
  - 重複や自己ループを整理し、後段処理に渡しやすくした版
- `多関係試作 (multirel_proto)`
  - prerequisite 以外の relation も扱う版
- `説明順分離版 (order_plan_proto)`
  - KG と説明順を分離して返す版

これは単なる UI 機能ではなく、**研究としてどの拡張が有効かを比較するための実験基盤**です。

### 2-4. prerequisite-only から、説明向けの多関係 KG に拡張した

元コードは `Is-a-Prerequisite-of` 固定でした。  
しかし LectureCraft では「前提関係」だけでは台本制御に足りません。

そこで多関係版では、例えば次の relation を扱えるようにしました。

- `explains`
- `example_of`
- `contrasts_with`
- `part_of`
- `used_for`
- `step_before`

これにより、KG を

- 前提知識グラフ

から

- 説明設計グラフ

へ近づけています。  
つまり、「何が何の前提か」だけでなく、「何を例として説明するか」「何を対比するか」まで表せる方向に拡張しています。

### 2-5. 根拠情報を持たせた

LectureCraft では、KG の結果をそのまま台本やハイライトに接続したいので、各 node / edge に

- `slide_refs`
- `evidence_text`
- `importance`
- `rationale`

を持たせる版を追加しました。

これにより、KG の各関係について

- どのスライドが根拠か
- どの語句が根拠か
- どの概念が重要か

を追えるようにしています。

これは研究的には、

- provenance を持つ KG
- explanation / evidence 付き KG

への拡張に対応します。  
LectureCraft 側では、将来的に

- 根拠に基づく台本生成
- 根拠スライドへのハイライト接続

へつなげるための準備です。

### 2-6. KG と説明順を分離した

元コードでは、抽出されたグラフそのものがそのまま知識構造であり、説明順も暗黙的にそこに含まれていました。  
しかし LectureCraft では、

- KG = 知識構造
- order plan = どう話すか

を分けた方が使いやすいです。

そこで `説明順分離版` では、KG 本体とは別に

- `order_plan.steps`

を返すようにしました。

各 step には例えば、

- `focus`
- `goal`
- `why_now`
- `related_concepts`
- `slide_refs`

などを持たせています。

これにより、KG は構造表現として残しつつ、後段の台本生成では **線形な説明順序** を別に利用できます。

### 2-7. 結果を project 単位で保存・管理するようにした

LectureCraft では研究実験だけでなく、実際の講義プロジェクトの一部として使うため、KG 結果を単なる一時出力ではなく **project に紐づく成果物** として管理する必要があります。

そのため、

- 結果を `backend/outputs/kg_preview/catalog/<result_id>/` に保存
- `result.json` に `project.id` を保存
- 読み込み API でも `project_id` で絞り込み

するようにしました。

これにより、

- どのプロジェクトで作られた KG か
- 同じ PDF でも別プロジェクトなら混ざらない

という運用ができるようになっています。

### 2-8. 結果比較 UI を専用ページとして整備した

元コードは単発実行して結果を見る形でしたが、LectureCraft では比較実験の方が重要なので、

- 結果一覧をサムネイルで俯瞰
- 見たい結果だけ選択
- 「図だけ」「図＋要約」「全部」のように表示項目を切替
- 保存済み結果を後から比較面に再配置

できる比較 UI を専用ページとして整備しました。

これは単なる見た目の改善ではなく、

- raw と改良版をすぐ比較できる
- 研究メモとして結果を見返しやすい
- 教員へ途中経過を説明しやすい

という研究運用上の利点があります。

### 2-9. Graphviz 依存を弱め、ブラウザ内可視化を追加した

元コードは Graphviz を前提に図示していましたが、LectureCraft では実行環境差があるため、Graphviz がない環境でも確認できるように、

- `.dot` は常に保存
- `dot` コマンドがあるときだけ PNG/SVG を保存
- frontend 側では triplet からブラウザ内 SVG を描画

するようにしました。

これにより、

- ローカル環境
- 開発環境
- 将来のサーバ環境

の差に左右されにくくなっています。

## 3. まとめると何を最適化したか

教授向けには、次のようにまとめると通しやすいです。

> 助教の方のコードは、講義資料から prerequisite knowledge graph を抽出する研究用プロトタイプとして非常に有用だった。  
> ただし LectureCraft では、KG を単に可視化するだけでなく、台本生成や説明設計に使う中間表現として扱いたかったため、そのままでは不足があった。  
> そこで、(1) PDF ベースの LectureCraft ワークフローへの統合、(2) project 単位での保存管理、(3) variant 比較基盤の導入、(4) 根拠情報付き KG への拡張、(5) prerequisite-only から多関係 KG への拡張、(6) KG と説明順の分離、(7) 比較実験しやすい UI 整備、という形で最適化を行った。

## 4. 現時点での位置づけ

現状は **「KG を LectureCraft に持ち込み、比較・検討・説明制御に使うための基盤を整えた段階」** です。

まだ今後の課題としては、

- KG を台本生成プロンプトへ本格的に注入すること
- relation の妥当性評価
- スライド領域単位の根拠付け
- 自動生成された order plan の有効性検証

などが残っています。

ただし少なくとも現時点で、

- 元コードをそのまま移植した段階

ではなく、

- LectureCraft の目的に合わせて構造的に拡張した段階

までは進んでいると説明できます。
